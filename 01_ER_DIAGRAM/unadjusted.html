ER Diagram ฉบับรวมก่อนปรับปรุง (Unadjusted Hospital ER Diagram - BEFORE)

สภาพก่อนรวมระบบ: ระบบย่อยถูกพัฒนาแบบ Data Silos ขาด Foreign Key กลาง, โครงสร้างขัดแย้ง 1NF/2NF, และข้อมูลซ้ำซ้อน

[!] Data Type ขัดแย้ง: VARCHAR (H1) vs INT (H2)
[!] ไร้ FK: H3 บันทึกชื่อคนไข้ Free-text ขาด patient_id
[!] ขาด FK Constraint: มี patient_id แต่ไม่ทำ Referential Integrity
[!] ขาด FK Constraint: ไม่มี Constraint ผูกความถูกต้องกับ H1
1:N doctor_id (แต่ H4 มีปัญหา M:N ภายใน)
[!] ไร้ FK: H5 บันทึกชื่อแพทย์ Free-text ไร้ Traceability
1:N doctor_id (นัดหมายระบุแพทย์)
[!] ขัด H01: มีฟิลด์หมอคนเดียว ไม่รองรับทีมแพทย์ร่วม
[!] เก็บ PII ซ้ำซ้อน: H6 บันทึกชื่อและเบอร์โทรซ้ำกับ H1
H2: appointments (ระบบนัดหมาย OPD) Redundant PII
[PK] appointment_id (INT)
• patient_id (INT - ชนิดข้อมูลไม่ตรงกับ VARCHAR ของ H1)
[FK] doctor_id (VARCHAR - อ้างอิง H7)
• patient_name, patient_phone (เก็บซ้ำซ้อน เสี่ยงไม่ตรงกัน)
appointment_date, appointment_time, appointment_status
H1: patients (ระบบทะเบียนผู้ป่วย - ศิลาหลัก) 1NF / 2NF Violation
[PK] patient_id (VARCHAR)
first_name, last_name, gender, birth_date
• phone, email (เก็บรวมในฟิลด์เดียว ขัดมาตรฐาน 1NF)
• insurance_name, policy_no (เก็บรวมในตาราง ขัด 2NF)
blood_group, weight_kg, height_cm, patient_status
⚠️ แต่ละแผนกไม่สามารถดึงข้อมูลอัตลักษณ์ไปใช้ร่วมกันได้จริง
H3: billing (ระบบการเงิน & บัญชี) No Foreign Key
[PK] bill_id (SERIAL)
• patient_name (พิมพ์ชื่อคนไข้เอง ไร้ FK อ้างอิง H1)
• insurance_company (ข้อความ Free-text สะกดเพี้ยน ไร้มาตรฐาน)
total_amount, payment_status
• amount_paid (ไม่รองรับการแบ่งจ่ายประกัน Split Bill - ขัด H02)
H4: prescriptions (ระบบยา & ใบสั่งยา) Unresolved M:N
[PK] rx_id (VARCHAR)
• patient_id (VARCHAR - ไม่มี Foreign Key Constraint ผูกกับ H1)
[FK] doctor_id (VARCHAR - อ้างอิง H7)
• medication_list (เก็บยาคั่นด้วยจุลภาค Comma-separated ขัด 1NF)
• ความสัมพันธ์ M:N ระหว่างใบสั่งยาและยายังไม่ถูกแยกเป็นตารางกลาง
H7: doctors (ระบบบุคลากร & แพทย์) 2NF / H05 Violation
[PK] doctor_id (VARCHAR)
doctor_name, specialty, email, salary_thb
• department_name (ไม่มีตารางแผนกแยกอิสระ ขัด 2NF/3NF)
• ไม่บันทึกประวัติการย้ายแผนกของแพทย์ (ขัด Change Card H05)
• ขาดระบบบริหารจัดการสิทธิ์และบัญชีผู้ใช้งานกลาง (Role/Security)
H5: lab_requests (ระบบสั่งตรวจแล็บ) Missing Doctor FK
[PK] lab_no (VARCHAR)
• patient_id (VARCHAR - ขาด Foreign Key Constraint ผูกกับ H1)
• doctor_name (บันทึกชื่อแพทย์เป็นตัวอักษร ไม่ผูก FK กับ H7)
test_type, result_value, test_date
• ไม่สามารถตรวจสอบย้อนกลับ (Traceability) หาแพทย์ผู้สั่งตรวจได้
H6: admissions (ระบบรับผู้ป่วยใน IPD & เตียง) Lost History (H03)
[PK] admission_id (VARCHAR)
• patient_id (ขาดการควบคุม Referential Integrity)
• patient_name, contact_phone (เก็บซ้ำซ้อนกับ H1)
• doctors (มีฟิลด์แพทย์คนเดียว ไม่รองรับทีมแพทย์ร่วม ขัด H01)
• bed_id (ย้ายเตียงแล้วเขียนทับเตียงเดิม สูญเสียประวัติ ขัด H03)
admission_date, discharge_date, admission_status
เส้นประสีแดง: ความสัมพันธ์ที่มีข้อผิดพลาดทางสถาปัตยกรรม (Data Type ขัดแย้ง / ขาด FK / ข้อมูลซ้ำซ้อน)
เส้นสีน้ำเงิน: ความสัมพันธ์ระดับข้อมูลปกติ (1:N doctor_id)
[!] ป้ายเตือน: จุดบกพร่องที่ต้องได้รับการแก้ไขในการรวมระบบ (Normalization 3NF, Associative Entity, Single Source of Truth)
