## ส่วนที่ 1: ตรวจสอบฐานข้อมูลก่อนทำงาน (6 คะแนน)

### ข้อ 1.1 อธิบายระบบย่อยของตนเอง
* **ชื่อระบบย่อย:** ระบบการเงินโรงพยาบาล (Hospital Billing / Payment) - โมดูล H3
* **หน้าที่ของระบบ:** ควบคุมและจัดการธุรกรรมทางการเงินทั้งหมดของโรงพยาบาล ครอบคลุมตั้งแต่การออกใบแจ้งหนี้ค่าใช้จ่ายในการเข้ารับการรักษาพยาบาล (Invoices), การจัดเก็บบันทึกรายละเอียดบริการ/ค่ายา/ค่าห้องย่อย (Invoice Items), การรับเงินผ่านช่องทางต่างๆ (Payments), การอำนวยความสะดวกยื่นเคลมประกันสุขภาพ (Insurance Claims), การออกใบเสร็จรับเงิน (Receipts/Receipt Items), การทำธุรกรรมคืนเงินกรณีผิดพลาด (Refunds), การรับและปล่อยวงเงินมัดจำล่วงหน้าสำหรับผู้ป่วยใน (Deposits), การกำหนดส่วนลดและโปรโมชัน (Discount Rules), การบันทึกประวัติการเปลี่ยนแปลงราคาสินค้าและบริการ (Price History), การกระทบยอดเงินโอนระหว่างระบบโรงพยาบาลกับธนาคาร (Bank Reconciliation) และการเก็บข้อมูลประวัติการบันทึกการทำงานของพนักงานเพื่อความปลอดภัย (Audit Log)

* **รายชื่อ Table และ Primary Key (PK):**
  1. `billing_services` (PK: `service_id`) - รายการแค็ตตาล็อกราคาบริการ/ค่าตรวจ/ค่ายา/ค่าห้อง
  2. `invoices` (PK: `invoice_id`) - เอกสารใบแจ้งหนี้หลักของการรักษาแต่ละครั้ง
  3. `invoice_items` (PK: `item_id`) - รายการค่าบริการย่อยที่เรียกเก็บในใบแจ้งหนี้
  4. `payments` (PK: `payment_id`) - ประวัติธุรกรรมการชำระเงิน
  5. `insurance_claims` (PK: `claim_id`) - รายการยื่นเคลมบริษัทประกัน
  6. `receipts` (PK: `receipt_id`) - ใบเสร็จชำระเงินที่ออกให้ผู้ป่วย
  7. `receipt_items` (PK: `receipt_item_id`) - รายการค่าใช้จ่ายย่อยบนใบเสร็จ
  8. `refunds` (PK: `refund_id`) - บันทึกรายการขอคืนเงินผู้ป่วย
  9. `deposits` (PK: `deposit_id`) - เงินมัดจำล่วงหน้าของผู้ป่วยนอนโรงพยาบาล (IPD)
  10. `discount_rules` (PK: `rule_id`) - กฎเกณฑ์และโปรโมชันส่วนลด
  11. `price_history` (PK: `history_id`) - บันทึกประวัติการปรับราคาบริการ
  12. `bank_reconciliation` (PK: `reconciliation_id`) - รายการนำเข้ายอดธนาคารเพื่อกระทบยอด
  13. `audit_log` (PK: `log_id`) - ข้อมูล Log บันทึกประวัติการแก้ไขตารางสำคัญ

* **Foreign Key (FK) และตารางที่เชื่อมโยง (Relationships):**
  - `invoice_items.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `invoice_items.service_id` -> `billing_services(service_id)` (Many-to-One)
  - `payments.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `insurance_claims.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `receipts.payment_id` -> `payments(payment_id)` (Many-to-One)
  - `receipts.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `receipt_items.receipt_id` -> `receipts(receipt_id)` (Many-to-One)
  - `refunds.payment_id` -> `payments(payment_id)` (Many-to-One)
  - `refunds.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `deposits.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `discount_rules.invoice_id` -> `invoices(invoice_id)` (Many-to-One)
  - `price_history.service_id` -> `billing_services(service_id)` (Many-to-One)
  - `bank_reconciliation.payment_id` -> `payments(payment_id)` (Many-to-One)
  - `audit_log.invoice_id` -> `invoices(invoice_id)` (Many-to-One)

* **ภาพแผนภาพแสดงความสัมพันธ์ (ER Diagram):**
  *(กรุณาแคปรูป ER Diagram จาก DBeaver ที่ปรับให้แสดงความสัมพันธ์ตารางครบถ้วน และวางรูปภาพตรงนี้)*

## ส่วนที่ 2: การเรียกดูและกรองข้อมูล (6 คะแนน)

### ข้อ 2.1 SELECT และ Alias
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงรายการใบแจ้งหนี้ที่ยังไม่ชำระเงิน พร้อมชื่อคอลัมน์ที่เข้าใจง่าย
* **โค้ด SQL:**
```sql
SELECT
    service_id AS "รหัสบริการภายใน",
    service_code AS "รหัสบริการอ้างอิง",
    service_name AS "ชื่อบริการทางการแพทย์",
    unit_price AS "ราคาค่าบริการต่อหน่วย (บาท)"
FROM billing_services;
```
* **ผลที่คาดหวัง:** ตารางรายการบริการทั้งหมด 12 แถว แสดงด้วยหัวคอลัมน์ที่เป็นภาษาไทยตามที่ระบุไว้ใน Alias
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ดึงข้อมูลแค็ตตาล็อกราคาบริการและเปลี่ยนหัวคอลัมน์ให้อ่านเข้าใจง่ายสำหรับแสดงผลบนระบบหน้าร้านภาษาไทย

### ข้อ 2.2 WHERE และ Operators
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงใบแจ้งหนี้ที่ชำระเงินแล้วและมียอดสุทธิมากกว่า 1000 บาท
* **โค้ด SQL:**
```sql
SELECT
    invoice_number AS "เลขที่ใบแจ้งหนี้",
    patient_id AS "รหัสผู้ป่วย",
    net_amount AS "ยอดสุทธิ",
    status AS "สถานะ"
FROM invoices
WHERE status = 'PAID' AND net_amount > 1000.00;
```
* **ผลที่คาดหวัง:** ใบแจ้งหนี้ที่มีสถานะ PAID และยอดสุทธิเกิน 1000 บาท
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ AND และเครื่องหมาย > เพื่อคัดกรองใบแจ้งหนี้มูลค่าสูงที่ชำระเรียบร้อย สำหรับวิเคราะห์ข้อมูลสถิติลูกค้ากลุ่มเป้าหมายที่มีกำลังจ่าย

### ข้อ 2.3 LIKE
* **คำถามที่ต้องการหาคำตอบ:** ต้องการค้นหาบริการที่มีคำว่า "ห้อง" ในชื่อบริการ
* **โค้ด SQL:**
```sql
SELECT
    service_code AS "รหัสบริการ",
    service_name AS "ชื่อบริการ",
    category AS "หมวดหมู่",
    unit_price AS "ราคาหน่วย"
FROM billing_services
WHERE service_name LIKE '%ห้อง%';
```
* **ผลที่คาดหวัง:** รายการบริการที่เกี่ยวกับห้องพักทั้งหมด
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** LIKE '%ห้อง%' ค้นหาคำที่มี "ห้อง" อยู่ตรงไหนก็ได้ในชื่อบริการ

### ข้อ 2.4 IN
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงใบแจ้งหนี้ที่มีสถานะ PAID หรือ PARTIALLY_PAID
* **โค้ด SQL:**
```sql
SELECT
    invoice_number AS "เลขที่ใบแจ้งหนี้",
    patient_id AS "รหัสผู้ป่วย",
    net_amount AS "จำนวนเงินสุทธิ",
    status AS "สถานะ"
FROM invoices
WHERE status IN ('PAID', 'PARTIALLY_PAID');
```
* **ผลที่คาดหวัง:** ใบแจ้งหนี้ที่ชำระแล้วและชำระบางส่วน
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** IN ใช้เลือกข้อมูลที่ตรงกับค่าหลายค่าใน list เดียวกัน

### ข้อ 2.5 BETWEEN
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงรายการชำระเงินที่มียอดระหว่าง 500 ถึง 2000 บาท
* **โค้ด SQL:**
```sql
SELECT
    payment_number AS "รหัสชำระเงิน",
    invoice_id AS "รหัสใบแจ้งหนี้",
    payment_method AS "วิธีการชำระ",
    amount_paid AS "ยอดที่จ่าย",
    paid_at AS "เวลาชำระเงิน"
FROM payments
WHERE amount_paid BETWEEN 500.00 AND 2000.00;
```
* **ผลที่คาดหวัง:** รายการชำระเงินที่มียอดเงินอยู่ในช่วง 500 ถึง 2000 บาท
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ BETWEEN ในการดึงธุรกรรมการชำระเงินระดับปานกลางเพื่อวิเคราะห์แนวโน้มการชำระเงินเฉลี่ยของโรงพยาบาล

### ข้อ 2.6 DISTINCT
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบว่ามีวิธีการชำระเงินใดบ้างที่ใช้ในระบบ (ไม่ซ้ำกัน)
* **โค้ด SQL:**
```sql
SELECT DISTINCT
    payment_method AS "วิธีชำระเงิน"
FROM payments;
```
* **ผลที่คาดหวัง:** รายการวิธีชำระเงินที่ไม่ซ้ำกันทั้งหมด
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** DISTINCT แสดงค่าที่ไม่ซ้ำกัน ช่วยตอบคำถามว่า "มีวิธีชำระเงินกี่ประเภท"

## ส่วนที่ 3: การเรียงลำดับและสรุปข้อมูล (6 คะแนน)

### ข้อ 3.1 ORDER BY และ LIMIT
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบ 5 รายการใบแจ้งหนี้ที่มียอดเงินสุทธิสูงสุด
* **โค้ด SQL:**
```sql
SELECT
    invoice_number AS "เลขที่ใบแจ้งหนี้",
    patient_id AS "รหัสผู้ป่วย",
    net_amount AS "จำนวนเงินสุทธิ",
    status AS "สถานะ"
FROM invoices
ORDER BY net_amount DESC
LIMIT 5;
```
* **ผลที่คาดหวัง:** 5 ใบแจ้งหนี้ที่มียอดเงินสูงสุด เรียงจากมากไปน้อย
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ORDER BY DESC เรียงลำดับจากมากไปน้อย LIMIT 5 แสดงเฉพาะ 5 รายการแรก

### ข้อ 3.2 MIN และ MAX
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบช่วงราคาของบริการทั้งหมดในระบบ (ราคาต่ำสุดและสูงสุด)
* **โค้ด SQL:**
```sql
SELECT
    MIN(unit_price) AS "ราคาต่ำสุด",
    MAX(unit_price) AS "ราคาสูงสุด",
    MAX(unit_price) - MIN(unit_price) AS "ช่วงราคา"
FROM billing_services;
```
* **ผลที่คาดหวัง:** ราคาต่ำสุด 30.00 (CPM) และราคาสูงสุด 5000.00 (ICU)
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** MIN/MAX หาค่าต่ำสุดและสูงสุดจากคอลัมน์ unit_price

### ข้อ 3.3 COUNT
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบจำนวนรายการเคลมประกันที่ค้างการตรวจสอบอนุมัติ
* **โค้ด SQL:**
```sql
SELECT COUNT(*) AS "จำนวนรายการเคลมประกันที่ค้างอยู่"
FROM insurance_claims
WHERE claim_status = 'PENDING';
```
* **ผลที่คาดหวัง:** จำนวนรายการเคลมสถานะ PENDING
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** นับจำนวนแถวที่ผ่านการกรองสถานะรอดำเนินการ เพื่อแจ้งเตือนพนักงานบัญชีให้เตรียมส่งเอกสารเคลมประกันเพิ่ม

### ข้อ 3.4 SUM
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบยอดเงินรวมที่ชำระเข้ามาทั้งหมดในระบบ
* **โค้ด SQL:**
```sql
SELECT
    SUM(amount_paid) AS "ยอดชำระรวมทั้งหมด",
    COUNT(*) AS "จำนวนรายการชำระ"
FROM payments;
```
* **ผลที่คาดหวัง:** ผลรวมยอดเงินที่ชำระทั้งหมด
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** SUM(amount_paid) คำนวณยอดเงินรวมที่ชำระเข้ามาทั้งหมดในระบบ

### ข้อ 3.5 AVG
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบค่าเฉลี่ยยอดเงินชำระต่อรายการ
* **โค้ด SQL:**
```sql
SELECT
    AVG(amount_paid)::NUMERIC(12,2) AS "ยอดชำระเฉลี่ย",
    MIN(amount_paid) AS "ยอดชำระต่ำสุด",
    MAX(amount_paid) AS "ยอดชำระสูงสุด"
FROM payments
WHERE amount_paid > 0;
```
* **ผลที่คาดหวัง:** ค่าเฉลี่ยยอดชำระต่อรายการ (ไม่รวมรายการที่ยอด 0)
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** AVG หาค่าเฉลี่ย ช่วยให้เห็นภาพว่าผู้ป่วยเฉลี่ยจ่ายเงินเท่าไหร่ต่อบิล

### ข้อ 3.6 CASE
* **คำถามที่ต้องการหาคำตอบ:** ต้องการจัดกลุ่มใบแจ้งหนี้เป็น 3 ระดับ ตามยอดเงินสุทธิ
* **โค้ด SQL:**
```sql
SELECT
    invoice_number AS "เลขที่ใบแจ้งหนี้",
    net_amount AS "จำนวนเงินสุทธิ",
    status AS "สถานะ",
    CASE
        WHEN net_amount >= 3000 THEN 'ยอดสูง'
        WHEN net_amount >= 1000 THEN 'ยอดปานกลาง'
        ELSE 'ยอดต่ำ'
    END AS "กลุ่มยอดเงิน"
FROM invoices
ORDER BY net_amount DESC;
```
* **ผลที่คาดหวัง:** ใบแจ้งหนี้แต่ละรายการถูกจัดกลุ่มเป็น ยอดสูง / ยอดปานกลาง / ยอดต่ำ
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** CASE ใช้จัดประเภทข้อมูลตามเงื่อนไขที่กำหนด ช่วยในการวิเคราะห์ระดับยอดเงิน

## ส่วนที่ 4: GROUP BY และ HAVING (4 คะแนน)

### ข้อ 4.1 GROUP BY
* **คำถามที่ต้องการหาคำตอบ:** ต้องการทราบจำนวนครั้งและยอดเงินรวมของการชำระเงินแยกตามวิธีชำระเงิน
* **โค้ด SQL:**
```sql
SELECT
    payment_method AS "วิธีการชำระเงิน",
    COUNT(*) AS "จำนวนครั้งที่ใช้งาน",
    SUM(amount_paid) AS "ยอดชำระรวมทั้งหมด (บาท)"
FROM payments
GROUP BY payment_method
ORDER BY SUM(amount_paid) DESC;
```
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** จัดกลุ่มข้อมูลตามวิธีการชำระเงินเพื่อดูสถิติความนิยมและยอดรวมของแต่ละช่องทางสำหรับเพิ่มประสิทธิภาพของแคชเชียร์

### ข้อ 4.2 HAVING
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงหมวดหมู่บริการที่มีบริการย่อยตั้งแต่ 3 รายการขึ้นไป
* **โค้ด SQL:**
```sql
SELECT
    category AS "หมวดหมู่ค่าบริการ",
    COUNT(*) AS "จำนวนรายการย่อย",
    ROUND(AVG(unit_price), 2) AS "ราคาเฉลี่ย (บาท)"
FROM billing_services
GROUP BY category
HAVING COUNT(*) >= 3;
```
* **ผลที่คาดหวัง:** รายการหมวดหมู่ที่มีจำนวนรายการบริการย่อย >= 3
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ HAVING ในการกรองกลุ่มข้อมูลผลลัพธ์ที่มีจำนวนรายการย่อยตามเป้าหมายเพื่อนำมาปรับปรุงโครงสร้างราคาส่วนลด

**คำอธิบายความแตกต่างระหว่าง WHERE และ HAVING:**
* **`WHERE`**: ใช้ในการกรองแถวข้อมูลแต่ละแถว **ก่อน** ที่ระบบจะนำไปจัดกลุ่ม (ก่อนคำสั่ง `GROUP BY`) โดยไม่สามารถใช้ร่วมกับฟังก์ชันการรวมค่า (Aggregate Functions) เช่น `SUM`, `COUNT`, `AVG` ในเงื่อนไขได้
* **`HAVING`**: ใช้ในการกรองผลลัพธ์ของกลุ่มข้อมูล **หลัง** จากที่คำนวณและจัดกลุ่มเสร็จเรียบร้อยแล้ว (หลังคำสั่ง `GROUP BY`) โดยสร้างเงื่อนไขตรวจสอบจาก Aggregate Functions ได้โดยตรง

## ส่วนที่ 5: ความสัมพันธ์และ JOIN (5 คะแนน)

### ข้อ 5.1 INNER JOIN
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงรายละเอียดใบแจ้งหนี้พร้อมรายการบริการที่สั่งซื้อ
* **โค้ด SQL:**
```sql
SELECT
    inv.invoice_number AS "เลขที่ใบแจ้งหนี้",
    inv.patient_id AS "รหัสผู้ป่วย",
    bs.service_name AS "ชื่อบริการ",
    bs.category AS "หมวดหมู่",
    ii.unit_price AS "ราคาหน่วย",
    ii.quantity AS "จำนวน",
    ii.line_total AS "ยอดรวมรายการ"
FROM invoice_items ii
INNER JOIN invoices inv ON ii.invoice_id = inv.invoice_id
INNER JOIN billing_services bs ON ii.service_id = bs.service_id
ORDER BY inv.invoice_number, bs.service_name;
```
* **ผลที่คาดหวัง:** รายการบริการที่มีในใบแจ้งหนี้เท่านั้น (ไม่รวมรายการที่ยังไม่มีใน invoice_items)
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** INNER JOIN แสดงเฉพาะข้อมูลที่ตรงกันทั้งสองตาราง

### ข้อ 5.2 LEFT JOIN
* **คำถามที่ต้องการหาคำตอบ:** ต้องการแสดงใบแจ้งหนี้ทั้งหมด พร้อมยอดชำระ (ถ้ามี) เพื่อดูว่าใบไหนยังไม่มีการชำระ
* **โค้ด SQL:**
```sql
SELECT
    inv.invoice_number AS "เลขที่ใบแจ้งหนี้",
    inv.patient_id AS "รหัสผู้ป่วย",
    inv.net_amount AS "ยอดหนี้สุทธิ",
    inv.status AS "สถานะ",
    p.payment_number AS "เลขที่ชำระ",
    p.amount_paid AS "ยอดชำระ"
FROM invoices inv
LEFT JOIN payments p ON inv.invoice_id = p.invoice_id
ORDER BY inv.invoice_number;
```
* **ผลที่คาดหวัง:** ใบแจ้งหนี้ทั้งหมด แสดงยอดชำระถ้ามี หรือ NULL ถ้ายังไม่มี
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** LEFT JOIN แสดงข้อมูลทั้งหมดจากตารางซ้าย แม้จะไม่มีข้อมูลตรงกันในตารางขวา

### ข้อ 5.3 ตรวจข้อมูลที่ไม่มีความสัมพันธ์
* **คำถามที่ต้องการหาคำตอบ:** ต้องการหาใบแจ้งหนี้ที่ยังไม่มีรายการชำระเงินเลย (ยังไม่มี payment)
* **โค้ด SQL:**
```sql
SELECT
    i.invoice_number AS "เลขที่ใบแจ้งหนี้ที่ยังไม่ชำระเงิน",
    i.patient_id AS "รหัสผู้ป่วย",
    i.net_amount AS "ยอดค้างชำระ (บาท)",
    i.status AS "สถานะปัจจุบัน"
FROM invoices i
LEFT JOIN payments p ON i.invoice_id = p.invoice_id
WHERE p.payment_id IS NULL
ORDER BY i.invoice_number;
```
* **ผลที่คาดหวัง:** ใบแจ้งหนี้ที่ยังไม่มียอดชำระในระบบ (ค่าข้อมูลชำระเงินเป็น NULL)
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ LEFT JOIN ร่วมกับ WHERE IS NULL เพื่อหาข้อมูลในตารางหลักที่ยังไม่มีความสัมพันธ์หรือยอดจ่ายในตารางลูก

## ส่วนที่ 6: การตรวจสอบและทำความสะอาดข้อมูล (3 คะแนน)

### ข้อ 6.1 ตรวจค่าที่หายไป (NULL)
* **คำถามที่ต้องการหาคำตอบ:** ต้องการตรวจว่ามีใบแจ้งหนี้ไหนที่ remark เป็น NULL หรือไม่
* **โค้ด SQL:**
```sql
SELECT
    invoice_number AS "เลขที่ใบแจ้งหนี้",
    patient_id AS "รหัสผู้ป่วย",
    remarks AS "หมายเหตุ"
FROM invoices
WHERE remarks IS NULL;
```
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ค้นหาข้อมูลที่ขาดหายไป (NULL) ในคอลัมน์หมายเหตุของตารางใบแจ้งหนี้ เพื่อเตรียมกรอกข้อมูลให้สมบูรณ์

### ข้อ 6.2 ตรวจข้อมูลซ้ำ
* **คำถามที่ต้องการหาคำตอบ:** ต้องการตรวจสอบว่าในตารางรายการบริการมีรหัสบริการซ้ำซ้อนกันในระบบหรือไม่
* **โค้ด SQL:**
```sql
SELECT
    service_code AS "รหัสค่าบริการทางการแพทย์",
    COUNT(*) AS "จำนวนแถวที่ซ้ำซ้อน"
FROM billing_services
GROUP BY service_code
HAVING COUNT(*) > 1;
```
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ GROUP BY และ HAVING COUNT > 1 ตรวจสอบความถูกต้องของคีย์ข้อมูลแค็ตตาล็อกเพื่อหลีกเลี่ยงข้อมูลซ้ำซ้อนที่เกิดจากผู้ใช้ป้อนผิดพลาด

### ข้อ 6.3 เสนอแนวทางแก้ไข
* **คำถามที่ต้องการหาคำตอบ:** เสนอแนวทางแก้ไขและทำความสะอาดข้อมูล
* **โค้ด SQL:**
```sql
BEGIN;

-- 1. แสดงราคาเดิมก่อนแก้ไข
SELECT service_code, service_name, unit_price 
FROM billing_services 
WHERE service_code = 'SVC-RM-01';

-- 2. เสนอทางแก้ไขโดยใช้คำสั่ง UPDATE ปรับราคาห้องพักจาก 2,500 บาท เป็น 2,800 บาท
UPDATE billing_services 
SET unit_price = 2800.00 
WHERE service_code = 'SVC-RM-01';

-- 3. เรียกดูผลลัพธ์จำลองราคาใหม่หลังปรับปรุงเพื่อตรวจสอบความถูกต้อง
SELECT service_code, service_name, unit_price 
FROM billing_services 
WHERE service_code = 'SVC-RM-01';

-- 4. ย้อนกลับคำสั่งเพื่อไม่ให้บันทึกจริง ป้องกันข้อมูลหลักเสียหาย
ROLLBACK;
```
* **ภาพผลลัพธ์:** *(วางรูปแคปเจอร์ตารางผลลัพธ์ของข้อนี้จาก DBeaver)*
* **คำอธิบายผลลัพธ์:** ใช้ BEGIN/ROLLBACK เพื่อจำลองและทดสอบการแก้ไขข้อมูลอย่างปลอดภัยโดยไม่ส่งผลกระทบถาวรต่อฐานข้อมูลจริง
